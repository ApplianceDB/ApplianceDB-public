Por que existe

"O que significa 5C na minha lavadora Samsung e como resolvo isso?" hoje é respondido por fazendas de conteúdo cheias de anúncios e sem estrutura. Nenhum conjunto de dados pronto para desenvolvedores mapeia (brand, appliance_type, code) → significado → solução priorizada com procedência honesta. O ApplianceDB faz isso.

Identidade composta do código

Lavadora Samsung 5C ≠ lava-louças Samsung 5C ≠ lavadora Samsung UK 5C. Cada registro é único em (brand, market, appliance_type, code).

Soluções indicadas pelo fabricante

Cada reparo traz um rank_basis explícito. A v1 traz a solução indicada pelo fabricante com um nível de dificuldade para fazer você mesmo.

Procedência por linha

Cada linha de código, solução e peça traz o nível da fonte e a URL exata da fonte — além de observações de preço datadas por varejista. Nunca há dados tirados de memória.

Fatos, não prosa

Significados e etapas são parafraseados com redação original — nenhum texto de manual protegido por direitos autorais é reproduzido.

Como é construído — a parte honesta

  • Nenhum código inventado, nunca. Cada código é derivado novamente de uma listagem de fonte consultada — páginas oficiais do fabricante para a maioria, referências secundárias declaradas para o restante —, nunca da memória do modelo. A coluna source_type indica o nível de procedência de cada linha.
  • Toda priorização tem uma base. Uma priorização sem evidência declarada é um palpite, e palpites não são publicados.
  • NULL em vez de palpite. Custos e números de peça ficam como NULL sempre que não existe observação verificada. Quando presentes, os números de peça são confirmados na própria loja de peças do fabricante e cada faixa de preço acompanha suas observações datadas por varejista.
  • Build determinístico, validado por testes. As verificações de unicidade composta, vocabulário controlado, contiguidade da priorização, procedência e cobertura rodam todas na CI.
